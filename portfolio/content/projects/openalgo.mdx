## Problem Statement

Quantitative traders often face high latencies, execution slip, and vendor lock-in when connecting automated algorithms to multi-broker APIs. Existing broker solutions are either overly complex, require heavy Java or C++ wrappers, or have restrictive rate limits that block high-frequency micro-hedging strategies.

## Approach

We built OpenAlgo as a zero-config, self-hosted execution framework. Written in highly optimized asynchronous Python, it exposes a lightweight FastAPI router and utilizes ZeroMQ socket queues for broker message dispatch. The engine abstracts away broker-specific API quirks, converting them into standard execution payloads.

## Technical Decisions

1. **SQLite with WAL Mode**: We selected SQLite in Write-Ahead Logging (WAL) mode for tick storage and audit logs, avoiding database server overhead while supporting concurrent reads and writes.
2. **ZeroMQ Message Queues**: Dispatched orders use an in-memory ZeroMQ PUSH-PULL queue to separate request receipt from execution dispatch, preventing broker API delays from blocking the user client thread.
3. **Pydantic Data Models**: Order validation uses Pydantic to filter out bad symbol symbols or parameters at the edge before sending requests down the queue.

## Results & Impact

- Achieved sub-millisecond local execution routing latency.
- Scaled to handle over 100,000 order dispatches daily under active stress tests.
- Powering live execution setups for retail quant traders across India.
